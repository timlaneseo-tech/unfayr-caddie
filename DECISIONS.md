# Decisions

Routine calls made while building, with the reason. Newest at the bottom.

## 2026-10-07

- **Working name `caddie`.** Short, lowercase, from "striking distance", the band of positions `/find` works in. Easy to rename: it appears in `plugin.json`, `marketplace.json`, the config-dir name, the user agent and the README.
- **Repo lives at `C:\Users\TimLane\caddie`.** No empty repo existed locally or on GitHub, so one was initialised on `main`. Remote to be confirmed by Tim.
- **CTR curve: First Page Sage, September 2026 edition.** It is published, current, and already reflects AI-answer SERPs. Positions 11 to 20 are not in the report, so they are extrapolated linearly from 0.15% to 0.05% and the code says so. The curve only ranks opportunities relative to each other; absolute values do not change the output order much.
- **Default Gemini model `gemini-2.5-flash`.** On the free tier its grounded requests carry a 1,500 requests-per-day allowance, versus 5,000 per month shared across the 3.x models. Daily, per-site work fits the 2.5 shape better. Model is configurable per site in `config.json`.
- **Daily cap defaults to 1,000 grounded calls** across all sites on the machine, tracked in the config dir, leaving headroom under the 1,500 quota for retries and other uses of the same key.
- **Extra runtime dependency: `node-html-parser`.** Zero transitive deps, small, gives `querySelector` over real-world HTML. A hand-rolled extractor would be the single most fragile part of the pipeline and the fixtures could not cover the mess of live CMS markup.
- **Extra dev dependencies: `typescript`, `@types/node`.** Typecheck only; Node strips types at run time so there is no build output.
- **Candidates are selected before pages are fetched, then annotated.** Wrong-page detection needs titles and H1s, which need the fetch, which should only happen for the capped candidate list. So `find-candidates` ranks first, `fetch-page` runs on the top N, and `flagNewPages` is a second pass over `candidates.json`.
- **Claude writes `changes.json`, a script writes the ledger.** The proposed changes are only known after Claude writes the page files, and the ledger needs content hashes and positions from the run. A structured file plus `ledger.ts record` keeps the ledger deterministic and idempotent instead of asking Claude to edit JSON in place.
- **Page URL normalisation strips query strings, fragments and trailing slashes** before aggregation. Search Console reports them as separate pages; the owner edits one template.
- **`sites/` is gitignored in this repo only.** Users decide whether to commit their own workspace; the repo must never carry someone's Search Console data.
- **Config dir is `%APPDATA%\caddie` on Windows and `$XDG_CONFIG_HOME/caddie` or `~/.config/caddie` elsewhere.** Standard locations, outside any project folder, so a stray `git add .` cannot pick up a token.
- **`overrides` pins `google-auth-library` to 10.5.0.** `googleapis` and `googleapis-common` otherwise resolve two copies of the auth library, and TypeScript refuses to pass an `OAuth2Client` built by one into an API typed against the other. One pinned copy removes the mismatch without any casting.
- **FAQ JSON-LD is included but never promised as a rich result.** Google retired FAQ rich results for most sites in 2023. The visible FAQ block is the value for readers and assistants; the JSON-LD is cheap, describes the block to anything reading structured data, and the page-diff skill forbids promising a rich result from it.
- **Skills are tested with the sample run, not subagent pressure scenarios.** The brief defines the test ("run it in sample mode, read the output as the site owner, fix anything you would not paste") and the harness guidance is not to spawn agents unprompted. The skills use recipe form for the output shape, which is the form that guidance recommends for shaping problems.
- **Fixture sites use the reserved `.example` TLD** so no sample ever points at a real business, and the HTML fixtures are written to contain the flaws the diagnoses need (answer buried in paragraph eight, title promising something else, headings that are topics rather than questions, no FAQ).
- **`scripts/check-page.ts` lints the writer's output.** Writing the first ten sample page files by hand showed the failure mode exactly: metas written to "about 158 characters" came out at 163 to 189, two answer paragraphs ran past 80 words, and nine Why lines were off by one. Counting is deterministic, so a script does it, and the command runs it before the ledger is recorded. The lint also checks that FAQ JSON-LD matches the visible questions word for word.
- **Renamed to Caddie, under the Unfayr brand (2026-10-07, Tim's call).** Tagline "Caddie reads the green. You sink the putt." Everything that said `strike` now says `caddie`: plugin name, config dir (`%APPDATA%\caddie`, `~/.config/caddie`), the `CADDIE_CONFIG_DIR` override, user agent, repo URL. Logo kit assets live in `assets/`; the kit's rules (clear space, never recolour, on-dark file on dark grounds) apply.
- **Credit line is now `Built by Unfayr · unfayr.com`**, matching Ref. The brief said bttrly; Tim's note that Caddie lives under Unfayr "like Ref does" supersedes that, and Ref's README and LICENSE use exactly this line. License stays MIT as the brief asked, with Unfayr as the copyright holder. One-line change in `scripts/lib/readme.ts` if Tim wants it back.
- **Default Gemini model is now `gemini-3.8-flash`, daily cap 150.** The first live run on 2026-10-07 returned `404 NOT_FOUND: models/gemini-2.5-flash is no longer available to new users` for every call. The 2.5 decision above is superseded: new keys only get the 3.x models, whose free grounding allowance is 5,000 searches a month shared, so 150 a day leaves a month of daily runs. The script now stops after the first model-unavailable error and names the fix instead of failing every question.
- **The AI check has two modes because Google removed grounding from the free tier.** Verified 2026-10-07 against the pricing page: Grounding with Google Search is "Not available" on the Free Tier for every current model; the 5,000 free searches a month exist only on the Paid Tier (billing account linked). The brief assumed a free grounded quota, which was true of the retired 2.5 models. Default `ai.mode` is `auto`: try grounded, and when the key's tier refuses, record plain answers plus whether the site is mentioned, with a note that says how to turn citations on. The zero-cost default stands; citations become an opt-in that costs a few cents of tokens on a billing-linked project.
- **Default model `gemini-3.1-flash-lite`, 4.5 s between calls.** AI Studio's rate-limit panel for a free project showed 500 requests a day for 3.1 Flash Lite against 20 for 3.8 Flash, and 15 versus 5 requests a minute. Pacing plus one 61-second retry on a per-minute limit keeps a 75-question run inside both.
- **A 402 on a "Free trial" project means a billing account is attached with no credit.** Seen live: the project was linked to a prepay-required billing account, so the free tier did not apply; disabling billing on the project in Cloud Console fixed it without touching the key. Both SETUP.md and the script's error text now say so.
- **Branded report: `scripts/report.ts` renders `report.html` and, when Chrome or Edge is installed, `report.pdf`.** Tim asked for a PDF people can keep. Two choices keep it inside the constraints: `marked` (one small, zero-dependency package) turns the page markdown into HTML rather than a hand-written parser, and the PDF comes from the browser already on the machine (`--headless --print-to-pdf`; Edge ships with Windows, Chrome paths are checked on macOS and Linux, `CADDIE_BROWSER` overrides). No PDF library, no service. Without a browser the script says to open the HTML and print to PDF.
- **Report design is a golf scorecard**, because Caddie reads the green: the cover ranks the pages with their clicks to gain, each page is a hole with its read and its fixes. Brand faces (Space Grotesk, IBM Plex Mono) from the logo kit, Ultra only on the hole numbers, one rule, and the "After" blocks. Fonts load from Google Fonts with system fallbacks so an offline PDF still renders.
- **`npm run check` writes its sample run to `.check/`** (gitignored) with a fixed date, so it stops overwriting a run a person is reading in `sites/`.
- **/monday built before /gaps (2026-10-07, Tim's call on my recommendation).** The ledger started filling today, so a memo that exists in two to four weeks reports on real edits; `/gaps` is weaker without citations, which the free tier no longer gives.
- **Applied status needs an explicit `lookFor`.** The first live memo marked two same-day changes as applied because the heuristic took the last quoted phrase in a summary, and `FAQ block ... before "Get a Quote"` quoted a location that was always on the page. `/find` now records `lookFor` (the new title, heading or first sentence) with every change; without it a change can only read as changed or unchanged, never applied.
- **The content hash covers prose, not the whole page.** The RTL home page rotates featured-inventory cards on every load, so its hash changed within hours of the proposal. The hash is now title, H1, H2s and paragraphs with at least twelve words and a sentence end. Ledgers recorded earlier the same day were re-recorded.
- **Operator queries (`site:` and friends) are ignored** in both commands. They are someone checking the index, not demand, and they were showing up as a page's top query.
- **Weekly movers need ten impressions this week and five last week.** With a floor of five, pages seen a handful of times showed as leaping twenty positions.
- **GA4 reads `landingPagePlusQueryString` with `sessions`, `engagedSessions`, `keyEvents`**, query strings stripped so paths line up with Search Console pages. `conversions` is the deprecated name for key events in the Data API. Nothing was tested live yet because no `ga4PropertyId` is configured.
- **/gaps built 2026-10-07.** Intent clustering needs an intent class on top of word overlap ("what is X" and "is X worth it" share every content word). A question counts as covered when a page's title, H1 or headings are about it and the AI answer, if any, mentions the site; ranking well on a page that is not about the question is the gap. Search Console questions under three impressions are ignored. Claude's cold answers are not collected by a script (that would need the Anthropic API or a manual step); the gap-brief skill compares Gemini's answer with the site instead. Live on RTL the question set is thin (14 open, mostly crane inspection intervals and Tadano), which is itself the finding: the site gets few question-form searches.
- **`config.notes` exists because the data was confidently wrong.** The first RTL run recommended building out the Bobcat of Brainerd location page; the store had been sold six months earlier, a fact in Tim's Q3 deck notes but nowhere on the site. Notes are facts the pages cannot show (locations sold, services not offered, brands dropped); the `/find` command reads them first and the intent-match skill says a note beats the data. A `redirect` change kind was added for the fix that case needs, and `/monday` counts it applied when the URL returns 404/410 or canonicalises elsewhere.
- **Template questions are filtered by topic shape and capped at three per topic.** "How much does crane inspection requirements OSHA cost?" is not a question anyone asks. Templates skip topics whose words make them read badly, and `questions.txt` is where the owner puts the real ones.
